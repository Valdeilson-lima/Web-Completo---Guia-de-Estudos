01. Terminal / Linha de Comando

O poder do texto puro

O terminal (ou prompt) é uma interface onde você dá comandos diretos ao computador. Parece intimidante no começo, mas apenas 10 comandos resolvem 90% do que você precisa.

Como abrir

VS Code:     Ctrl + '   (acento grave)
Windows:     Win + R, digite "cmd" ou "powershell"
Mac:         Cmd + Espaço, digite "Terminal"
Linux:       Ctrl + Alt + T

Comandos essenciais

# 📁 NAVEGAÇÃO
pwd                     # Mostra onde você está (print working directory)
ls                      # Lista arquivos da pasta atual
ls -la                  # Lista detalhado (inclui ocultos)
cd nome-da-pasta        # Entra na pasta (change directory)
cd ..                   # Volta uma pasta
cd ~                    # Vai para sua pasta pessoal (home)

# 📂 ARQUIVOS E PASTAS
mkdir nome              # Cria uma pasta (make directory)
touch arquivo.txt       # Cria um arquivo vazio
code .                  # Abre a pasta atual no VS Code
code arquivo.html       # Abre um arquivo no VS Code

# 🗑️ REMOVER (cuidado!)
rm arquivo.txt          # Remove arquivo
rm -rf pasta            # Remove pasta e tudo dentro (⚠️ permanente!)

# 🔀 COPIAR / MOVER
cp origem destino       # Copia arquivo
mv origem destino       # Move ou renomeia
🧠 Dica: Use a tecla Tab para auto-completar nomes de arquivos e pastas. Use seta ⬆️ para repetir comandos anteriores.

02. Git & GitHub

Controle de versão — o "Ctrl+Z" profissional

O que é Git?

Git é um sistema que guarda versões do seu código como se fossem fotos. Você pode voltar no tempo, criar "galhos" (branches) para testar coisas novas, e colaborar com outras pessoas sem medo de estragar tudo.

Instalação

Windows: baixe em git-scm.com
Mac:     brew install git
Linux:   sudo apt install git

Comandos que você vai usar todo dia

# Configurar (primeira vez)
git config --global user.name "Seu Nome"
git config --global user.email "seu@email.com"

# Começar um repositório
git init                 # Inicia o Git na pasta atual
git status               # Mostra o que mudou (use SEMPRE!)

# O ciclo de vida
git add arquivo.html     # Prepara o arquivo para o commit
git add .                # Prepara TODOS os arquivos
git commit -m "Mensagem" # Tira a "foto" das mudanças

# Ver histórico
git log                  # Lista os commits
git log --oneline        # Versão resumida
git diff                 # Mostra o que mudou (antes do add)

GitHub — seu código na nuvem

1. Crie uma conta em github.com
2. Crie um repositório (botão "New")
3. Conecte o local com o remoto:

git remote add origin https://github.com/seu-user/seu-repo.git
git branch -M main
git push -u origin main

# Depois do primeiro push:
git push                # Envia commits para o GitHub
git pull                # Puxa atualizações do GitHub
git clone URL           # Baixa um repositório inteiro

.gitignore

Crie um arquivo .gitignore na raiz do projeto para ignorar pastas que não devem ir para o Git: 

node_modules/
.env
.DS_Store
dist/

Branches — "galhos" para trabalhar sem medo

# Ver a branch atual
git branch

# Criar e entrar numa branch nova
git checkout -b nova-funcionalidade
# (equivalente a: git branch nova-funcionalidade && git checkout nova-funcionalidade)

# Trocar de branch
git checkout main
git switch main          # comando moderno

# Ver diferenças entre branches
git diff main nova-funcionalidade

Merge e conflitos

# Juntar uma branch na branch atual
git checkout main
git merge nova-funcionalidade

# ⚠️ Conflito: quando duas branches mudaram a MESMA linha
# O Git marca o arquivo assim:
# <<<<<<< HEAD
#   minha versão
# =======
#   versão da outra branch
# >>>>>>> nova-funcionalidade

# Você resolve manualmente (deixa o que faz sentido),
# depois marca como resolvido:
git add arquivo-resolvido.js
git commit

# Desfazer um merge
git merge --abort

Workflow típico de equipe (GitHub Flow)

# 1. Crie uma branch a partir da main
git checkout -b minha-tarefa

# 2. Faça commits pequenos e claros
git add .
git commit -m "feat: adiciona busca de usuários"

# 3. Envie para o GitHub e abra um Pull Request
git push -u origin minha-tarefa
# → no GitHub: botão "Compare & pull request"

# 4. Depois do review e merge, atualize sua main
git checkout main
git pull
🧠 Dica: git status é seu melhor amigo. Use ele antes de qualquer comando para saber exatamente o que está acontecendo. E sempre escreva mensagens de commit claras.

03. DevTools do Navegador

O raio-X do site — veja como qualquer página foi feita

Abrindo o DevTools

Chrome / Firefox / Edge:
  F12  ou  Ctrl + Shift + I  ou  clique direito > "Inspecionar"

Elements (Elementos)

Mostra o HTML da página. Você pode:

🔹 Inspecionar qualquer elemento clicando com direito > "Inspecionar"
🔹 Editar texto e atributos ao vivo (muda na tela, mas não salva)
🔹 Ver o CSS aplicado a cada elemento na aba "Styles"
🔹 Desativar/ativar estilos clicando nas caixinhas
🔹 Ver o Box Model (margin, border, padding) visualmente
💡 Teste agora

Aperte F12 nesta página, vá na aba Elements, e clique em qualquer texto para ver o HTML e CSS por trás dele.

Console

O console é onde você vê mensagens do JavaScript e pode testar código ao vivo: 

// Escreva diretamente no console e veja o resultado na hora
console.log('Olá do console!');
2 + 2
document.querySelector('h1').textContent = 'Novo título';

// Ver erros — links em vermelho com a linha do erro
// Útil para debugar JavaScript

Network (Rede)

Mostra todas as requisições que a página faz (arquivos, imagens, APIs): 

🔹 Veja quanto tempo cada arquivo levou para carregar
🔹 Filtre por tipo (JS, CSS, Imagem)
🔹 Veja o código de resposta (200 = ok, 404 = não encontrado)
🔹 Simule conexão lenta (dropdown "Online" > "Slow 3G")

Sources (Fontes)

Mostra todos os arquivos do site. Útil para:

🔹 Ver arquivos JS e CSS completos
🔹 Colocar breakpoints no JavaScript (pausa a execução)
🔹 Ver o valor das variáveis passo a passo

Lighthouse

Faz um "checkup" completo da página:

🔹 Performance (velocidade)
🔹 Acessibilidade
🔹 Boas práticas
🔹 SEO
🔹 Gera um relatório com notas e sugestões
🧠 Dica: O DevTools é a ferramenta mais importante para um desenvolvedor web. Aprender a usá-lo bem vai economizar horas de debugging. Passe um tempo explorando cada aba.

04. Node.js, npm & npx

O JavaScript fora do navegador — e o gerenciador de pacotes

O que é Node.js?

Node.js é um runtime: ele roda JavaScript fora do navegador (no servidor, em ferramentas de linha de comando, etc.). Todo projeto web moderno usa Node — inclusive este guia usa ferramentas Node para formatação e git hooks!

Instalação e verificação

# Baixe em nodejs.org (versão LTS recomendada)

# Verificar se instalou
node -v        # v20.x.x (versão do Node)
npm -v         # 10.x.x  (versão do npm)

# O npm vem junto com o Node

package.json — o "coração" do projeto

// Criado automaticamente por:
npm init -y

{
  "name": "meu-projeto",
  "version": "1.0.0",
  "scripts": {
    "dev": "vite",              // npm run dev
    "build": "vite build",      // npm run build
    "test": "vitest"            // npm test
  },
  "dependencies": {
    "dayjs": "^1.11.10"         // dependências de produção
  },
  "devDependencies": {
    "vite": "^5.0.0"            // só para desenvolvimento
  }
}

npm — instalar e gerenciar pacotes

# Instalar
npm install pacote          # dependência de produção
npm install -D pacote       # devDependency (ferramentas)
npm install                 # instala TUDO do package.json
npm install --save-exact pkg # trava versão exata

# O que acontece:
#   1. Baixa o pacote para node_modules/
#   2. Registra no package.json
#   3. Gera/atualiza o package-lock.json (versões exatas)

# Desinstalar / atualizar
npm uninstall pacote
npm update
npm outdated                # ver o que está desatualizado

# npm audit — checa vulnerabilidades
npm audit
npm audit fix               # corrige automaticamente

npx — rodar sem instalar

# npx executa um pacote SEM precisar instalá-lo globalmente

npx create-vite@latest meu-app   # cria projeto Vite
npx serve .                      # sobe um servidor estático
npx prettier --write arquivo.js  # formata um arquivo

# Diferença:
#   npm install -g pacote  → instala global (fica para sempre)
#   npx pacote             → baixa, roda e descarta

Scripts — atalhos do package.json

# Todos os comandos frequentes viram scripts
"scripts": {
  "dev": "vite",
  "build": "vite build && vite preview",
  "lint": "eslint . --fix",
  "format": "prettier --write ."
}

# Rodar:
npm run dev
npm run build
npm run lint
npm run format

# Atalhos especiais (não precisam de "run"):
npm start     # roda o script "start"
npm test      # roda o script "test"
🧠 Dica: node_modules/ é enorme e regenerável — nunca commite essa pasta (por isso existe o .gitignore). Sempre commite o package.json e o package-lock.json.

05. Variáveis de Ambiente & Deploy

Segredos fora do código + como colocar seu site no ar

Variáveis de ambiente (.env)

# Guardam configurações e segredos FORA do código.
# Ex.: URL da API, chaves, tokens — nunca versionados!

# Arquivo .env (na raiz do projeto, ignorado pelo Git)
API_URL=https://api.exemplo.com
API_KEY=abc123-segredo

# No Node.js (após instalar dotenv)
import 'dotenv/config';
console.log(process.env.API_URL);   // "https://api.exemplo.com"

# No front-end com Vite — use o prefixo VITE_
VITE_PUBLIC_KEY=chave-publica
// acessível como import.meta.env.VITE_PUBLIC_KEY

# Arquivos típicos:
#   .env          → ambiente local
#   .env.example  → modelo committado (sem segredos!)
#   .env.production → produção

Por que não commitar o .env?

# Se um token vazar para o GitHub, qualquer pessoa pode usá-lo!
# Por isso o .gitignore sempre inclui:
.env
.env.*

# ✅ Commite apenas:
.env.example   # com valores fictícios como documentação

O que é deploy?

# Deploy = publicar seu site para o mundo acessar.
# Seu código (local) → servidor (internet)

# Tipos:
#   1. Estático (HTML/CSS/JS puro) → só subir arquivos
#   2. Front-end com build → npm run build gera pasta dist/
#   3. Full-stack (Node) → servidor roda o app (Vercel, Render, Railway)

# Fluxo típico de deploy:
#   git push → plataforma detecta → roda build → publica
#   (ou: upload manual via FTP / painel do provedor)

Onde hospedar (gratuitos)

# GitHub Pages        → grátis, para sites estáticos
#   Settings > Pages > branch main > Salvar

# Vercel / Netlify    → grátis, deploy automático pelo Git
#   conecta o repositório e faz build sozinho

# Render / Railway    → para apps Node com backend

# Para GitHub Pages (site estático):
#   1. Push do código para o GitHub
#   2. Repo > Settings > Pages > Source: main
#   3. Seu site fica em: usuario.github.io/nome-do-repo

Checklist antes de publicar

☐ Rodou npm run build sem erros?
☐ Testou em celular (responsividade)?
☐ Verificou o Lighthouse (performance + acessibilidade)?
☐ Sem console.log / debugger esquecidos?
☐ .env fora do Git?
☐ Título e meta description do site?
☐ Links funcionando (nenhum 404)?
🚀 Dica: Para aprender, publique tudo! Um site no ar (mesmo simples) vale mais no portfólio do que 10 projetos só no seu computador.
